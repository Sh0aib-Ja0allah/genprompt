# Contributing to genprompt

Thanks for helping. Most contributions are **rule changes**: a lesson from real use that should
apply to everyone.

## Before you open anything

- **Questions or ideas:** use [Discussions](https://github.com/Sh0aib-Ja0allah/genprompt/discussions).
- **Bugs** (a command fails, a wrong gate, a doctor ERROR) and **rule suggestions:** open an
  [issue](https://github.com/Sh0aib-Ja0allah/genprompt/issues/new/choose) from a template.
- **Never paste private code, repo names, paths or secrets.** Anonymise first: the shape of the
  problem is enough.

## Making a change

```bash
git clone https://github.com/Sh0aib-Ja0allah/genprompt
cd genprompt
# edit the rules; if you add or rename a command, edit the tables in tools/build_shims.py, then:
python3 tools/build_shims.py
python3 tools/doctor.py --suite      # must report 0 ERROR
claude plugin validate .
claude --plugin-dir .                # try your copy without installing it
```

Rules for a pull request:
- **One rule change per PR**, with a line in `CHANGELOG.md`:
  `- <YYYY-MM-DD> · <file> · <what changed and why>`.
- **Never renumber sections or re-letter archetypes.** Archived prompts cite them. A new block
  takes the next free §4 number, and a new archetype takes the next free letter.
- **Never edit `commands/` by hand.** It is generated by `tools/build_shims.py`.
- **Keep it generic.** No project names, personal paths or machine-specific facts. Doctor rejects
  user-specific absolute paths.
- **Keep the generator read-only** on repos. A change that lets it write outside `~/.genprompt/`,
  or run builds, tests or mutating git, will not be merged.

Where a lesson belongs is mapped in [guide/00-index.md](guide/00-index.md) §12.
